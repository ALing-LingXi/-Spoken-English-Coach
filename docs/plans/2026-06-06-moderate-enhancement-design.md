# AI 英语口语陪练 - 中等增强方案设计

## 背景与目标

在 MVP 语音陪练基础上，增强学习体验、交互体验、产品功能和工程化水平，使产品具有差异化竞争力。

**目标：**
- 多轮对话 + 语法纠错 + 发音评分，提升学习效果
- 打断机制 + 波形可视化，提升交互自然度
- 设置面板 + 场景切换 + 记录持久化，完善产品功能
- 重连 + 重试 + 错误恢复，提升健壮性
- 深色主题 + 动效，解决页面单调问题

**成功标准：** 每个功能独立可交付，solo 开发者可逐个实现，不依赖复杂基础设施。

**约束：** 纯网页端项目，所有功能基于浏览器 API，无需后端数据库。

## 现状与约束

### 已完成
- 后端：Express + WebSocket + ASR/LLM/TTS 完整流水线（SiliconFlow API）
- 前端：Vue 3 + Pinia + Vite 框架，WebSocket 客户端
- 6 个前端文件为空（Store、Hooks、Components、App.vue）

### 约束
- SiliconFlow API 限制（速率、模型能力）
- 浏览器麦克风权限需要用户授权
- base64 音频传输有大小限制
- 无用户系统，数据仅存 localStorage

## 方案对比

### 方案一：轻量增强
- 优点：改动最小，1-2 小时/功能
- 缺点：无差异化，仍是基础陪练

### 方案二：中等增强（推荐）
- 优点：有区分度（语法纠错、发音评分、场景模式），每块独立可实现
- 缺点：发音评分需验证 API 可行性

### 方案三：全面增强
- 优点：完整产品级
- 缺点：工作量大，实时 ASR 需不同 API，solo 风险高

## 推荐方案

**方案二：中等增强**，理由：
1. 每个功能可拆成独立小任务，AI 逐个实现不易出错
2. 语法纠错和发音评分是口语陪练的核心差异化
3. 打断机制和场景切换显著提升使用体验
4. 不依赖复杂基础设施（无需数据库、用户系统）

### 关键组件

#### 1. 学习体验增强

**多轮对话上下文：**
- 前端 Store 维护 `messages: [{ role, content, correction? }]`
- 发送音频时带上历史消息：`{ type: "audio", data: { audio, messages } }`
- 后端直接传给 `generateReplyStream(messages)`

**语法纠错反馈：**
- 修改 LLM system prompt，要求在回复末尾用 `[纠错]` 标注语法错误
- 前端解析 `[纠错]` 标记，在聊天面板中橙色高亮显示
- 纠错内容存入消息的 `correction` 字段

**发音评分：**
- 优先检查 ASR API 是否返回置信度，有则直接用
- 若无置信度，在 LLM prompt 中加"评估用户英语水平 1-5 分"
- 评分结果显示在消息气泡下方

#### 2. 交互体验优化

**打断机制：**
- usePlayer 新增 `stop()` 方法和 `isPlaying` 状态
- VoiceButton mousedown 时先检查 isPlaying，若在播放则 stop()
- WebSocket 新增 `interrupt` 消息类型

**音频波形可视化：**
- useRecorder 使用 AudioContext + AnalyserNode 获取频域数据
- 暴露 `waveformData` 响应式引用
- VoiceButton 用 canvas 渲染环形频谱动画

**WebSocket 断线重连：**
- onclose 时指数退避重连（1s → 2s → 4s → 最大 30s）
- 每 30s 发送心跳 ping，超时未收到 pong 则重连
- 暴露 isConnected 状态

#### 3. 产品功能

**设置面板（右侧抽屉式）：**

| 设置项 | 类型 | 作用 |
|--------|------|------|
| 语速 | 滑块 0.5x-2x | TTS speed 参数 |
| 音色 | 下拉选择 | TTS voice 参数 |
| 难度 | 初级/中级/高级 | 影响系统 prompt |
| 纠错开关 | 开关 | 是否开启语法纠错 |

设置存 localStorage，刷新后保留。

**场景模式切换（顶部标签）：**

| 场景 | prompt 方向 |
|------|------------|
| 日常闲聊 | 轻松自然，话题广泛 |
| 商务英语 | 正式用语，会议/邮件场景 |
| 旅行英语 | 机场/酒店/点餐等实用场景 |
| 面试模拟 | 面试问答，专业表达 |

场景切换时清空对话历史。

**聊天记录持久化：**
- localStorage 存储对话记录
- 页面刷新后恢复
- 提供"清空记录"按钮
- 每个场景独立存储

#### 4. UI 视觉设计

**设计风格：** 深色主题 + 渐变色 + 毛玻璃效果

| 组件 | 视觉设计 |
|------|---------|
| 整体 | 深色渐变背景（深蓝→深紫），毛玻璃卡片 |
| VoiceButton | 中心大圆形按钮，录音时脉冲波纹 + 渐变光晕 |
| ChatPanel | 气泡式消息，用户蓝色右对齐，AI 灰色左对齐，纠错橙色高亮 |
| SettingsPanel | 右侧抽屉滑出，毛玻璃背景 |
| SceneSelector | 顶部横向标签，选中态下划线动画 |
| 状态指示 | 连接/录音/处理中 不同颜色呼吸灯 |

**动效清单：**
1. 录音按钮：按下缩放 + 波纹扩散
2. 消息出现：从下方滑入 + 淡入
3. AI 回复：打字机效果（流式逐字显示）
4. 波形可视化：录音时按钮周围环形频谱
5. 场景切换：淡入淡出过渡

#### 5. 工程化提升

**请求重试（server/utils/retry.js）：**
- 通用 `retry(fn, maxRetries=3, baseDelay=1000)` 函数
- 指数退避，只对网络错误和 5xx 重试，4xx 不重试
- ASR/LLM/TTS 三个服务都用 retry 包裹

**音频队列管理：**
- usePlayer 维护播放队列
- 当前播放完自动播下一条
- stop() 清空队列并停止
- interrupt() 停止当前但保留队列

**错误恢复：**

| 场景 | 处理方式 |
|------|---------|
| WS 断连 | 自动重连 + 重发未完成请求 |
| ASR 失败 | 提示"识别失败，请重试" + 重试按钮 |
| LLM 超时 | 5s 无 chunk 则提示 + 重试 |
| TTS 失败 | 文字正常显示，提示"语音合成失败" |
| 麦克风权限 | 引导开启权限的提示页 |

**日志系统：**
- 后端统一格式：`[时间] [级别] [模块] 消息`
- 前端 console 分级即可

### 数据流 / 接口

**WebSocket 消息协议扩展：**

```js
// 客户端→服务端
{ type: "audio", data: { audio: "base64...", messages: [...] } }  // 带上下文
{ type: "setting", data: { speed: 1.0, voice: "alex", difficulty: "medium" } }
{ type: "scene", data: { scene: "business" } }
{ type: "interrupt", data: {} }

// 服务端→客户端（新增）
{ type: "score", data: { score: 4, feedback: "发音清晰，语调自然" } }
{ type: "pong", data: {} }
```

### 异常与边界处理

- 音频过大（>5MB base64）：前端录音限制最长 60s
- LLM 流式中断：前端拼接已收到的内容，标记为不完整
- 并发请求：同一时间只允许一个音频处理流程，后续请求排队或拒绝
- localStorage 满了：只保留最近 100 条消息，旧的自动清理

### 测试策略

- 每个功能完成后手动验证
- 后端：用 wscat 工具测试 WebSocket 消息
- 前端：浏览器 DevTools 检查网络和音频
- 关键路径：录音→识别→回复→播放 的完整流程

## 风险与待确认项

1. **SiliconFlow ASR 是否返回置信度**：影响发音评分方案选择，需验证
2. **SiliconFlow TTS 是否支持 speed 参数**：影响语速调节功能，需验证
3. **浏览器 AudioContext 兼容性**：波形可视化依赖 Web Audio API，Safari 可能有差异
4. **base64 音频大小**：60s 录音的 base64 约 5MB，WebSocket 传输可能有延迟
